# Pixiv 批量下载器

给一个作者主页，把该作者名下的**插画、漫画（含连载系列）、动图、小说**全部下载到本地。
带网页 GUI，登录、选目录、看进度、暂停重试都在页面上完成，不需要敲命令。

## 环境要求

- Windows（路径与文件名的处理按 Windows 规则做）
- Python 3.10+
- **Chrome 或 Edge**（登录时直接接管系统浏览器，不下载额外内核）
- Python 包：`fastapi` `uvicorn` `httpx` `pillow` `websockets`

## 安装

```powershell
cd pixiv-downloader
python -m pip install -r requirements.txt
```

## 启动

```powershell
python run.py
```

会自动打开浏览器到 GUI 页面（端口默认 8765，被占用时自动换一个）。
关掉那个命令行窗口就是停止服务。

## 登录

点页面右上角的「登录 Pixiv」，会弹出一个**独立的浏览器窗口**停在 Pixiv：

- 优先用 **Pixiv 账号密码**登录 —— 成功率最高
- 也可以用 **Google 登录** —— Google 会识别自动化环境，有一定概率提示「此浏览器或应用可能不安全」，遇到就改用账号密码

程序启动 Chrome 时带上调试端口，每 2 秒读一次 cookie，一旦 `/ajax/user/self` 验证通过就自动关窗。
浏览器资料保存在 `.profile/pixiv/`，所以**下次启动通常已经是登录态**。

备用方案：点「用 Cookie 登录」，把浏览器里 `pixiv.net` 的 Cookie 粘进去。Google 登录被拦时用这个。

### 关于登录的两个事实

**为什么不能把登录页嵌在网页里**：`pixiv.net` 和 `accounts.google.com` 都返回
`X-Frame-Options: DENY`，浏览器的 iframe 会被直接拒绝。这是网站方限制。

**不登录也能下载公开作品**：实测未登录即可读取公开作品列表、详情和原图，
登录主要影响 R-18 / R-18G 和受限内容。

## 使用

1. 填作者主页，例如 `https://www.pixiv.net/users/114430563`，点「解析」
2. 选保存目录（点「选择…」会弹出系统原生文件夹选择框）
3. 需要的话调整选项
4. 点「生成计划」—— 只抓清单不下载，先看看将要下什么
5. 点「开始下载」

## 选项

| 选项 | 说明 |
|---|---|
| 保存目录 | 所有文件落在这一层 |
| R-18 / R-18G | 全部 / 只要全年龄 / 只要 R-18。**注意**：只有当账号在 Pixiv 设置里开启了「显示 R-18」时，接口才会返回这些作品 |
| 时区 | 决定文件名里的日期。默认按 Pixiv 的 JST 切日 |
| 并发数 | 同时下载几个文件，默认 3，最大 8 |
| 请求间隔 | 两次接口请求之间至少等多久，默认 600ms |
| 起始/结束日期 | 按作品发布时间筛选 |
| 插画 / 漫画 / 小说 / 动图 | 只下载勾选的类型。动图会解码后重新合成 GIF |

## 命名规则

图片：`年-月-日_标题_序号.扩展名`

页数**超过 8 张**的作品，文件放进一个单独文件夹，文件夹名是去掉结尾序号的那一段：

```
2024-05-01_Blue_1.jpg
2024-05-01_Blue_2.jpg
2024-05-02_Big/
    2024-05-02_Big_1.png
    2024-05-02_Big_2.png
    ...
```

页数正好 8 张**不**建文件夹（规则是“大于 8”）。

同一天、同一标题的多个作品，序号**接续累计**而不是从 1 重来：

| 作品 | 日期 | 标题 | 页数 | 产出 |
|---|---|---|---|---|
| A | 2024-05-01 | Blue | 3 | `2024-05-01_Blue_1~3` |
| B | 2024-05-01 | Blue | 2 | `2024-05-01_Blue_4~5` |

标题里的 `\ / : * ? " < > |` 会被替换成 `_`，超长标题按 UTF-8 字节截断，
Windows 保留名（`CON`、`NUL` 等）自动加后缀。

小说：`年-月-日_标题.md`，内容版式：

```markdown
[标题](https://www.pixiv.net/novel/show.php?id=12345)
作品简介

===

正文……
```

小说如果有分页，会合并成一个文件。

## 连载系列

连载 / 系列作品**不会**出现在作者作品的普通列表里（实测：某作者有 6 话系列，
`illusts` 和 `manga` 都是空的）。程序会读取 `mangaSeries`，从系列首话沿
`seriesNavData.next` 把整条链走完，所以系列作品不会漏。

## 查重与断点续传

重跑同一个作者时，已经下载过的文件会被跳过（状态显示 `skipped`），不会重复下载。

实现在输出目录里的 `.pixiv_dl_index.json`：它记录 **作品 id → 每页的序号和文件名**。

为什么非要这个索引：文件名里的序号是按 `(日期, 标题)` 累计分配的。如果每次重跑都从
「已有最大序号 + 1」重新分配，文件名就会变，判重立刻失效，整批文件会被重下一遍。
索引把编号固定下来，重跑时文件名不变，判重才真正有效。

| 情况 | 表现 |
|---|---|
| 文件已下载完 | 跳过 |
| 文件在但大小为 0（上次中断） | 重新下载 |
| 文件被手动删掉 | 用**原来的文件名**重下，不产生新编号 |
| 首次运行且目录里已有旧文件 | 自动按序号认领，不重下 |
| 换一个保存目录 | 重新建索引，整批重下（正常） |

`.pixiv_dl_index.json` 跟着输出目录走，可以连文件一起搬走；删掉它也不致命，
下次运行会按文件名重新认领磁盘上已有的文件。

## 账号安全

批量下载原图属于超出正常浏览强度的访问，**建议保持默认的保守参数**（并发 3、间隔 600ms）。
遇到 429/5xx 会指数退避重试；如果频繁触发，把并发降到 1、间隔调到 1500ms 以上。
这个工具只适合备份自己有权访问的内容。

## 隐私与数据

程序只把这些东西写在自己的目录里：

| 路径 | 内容 | 入不入库 |
|---|---|---|
| `.state/config.json` | Pixiv 会话 Cookie | 否，`.gitignore` 已排除 |
| `.profile/pixiv/` | 浏览器登录态（一套独立 profile） | 否，同上 |
| `<你选的目录>/.pixiv_dl_index.json` | 下载索引 | 跟着输出目录走 |

**不要提交 `.state/` 和 `.profile/`。** 它们等于你的登录凭据。
想彻底登出或换号，删掉这两个目录就行，程序会回到未登录状态。

## 可移植性

程序里没有任何写死的目录、盘符或用户名：

- 保存目录完全由你在界面上选
- 登录用的浏览器从系统默认浏览器读（Edge / Chrome），都不是才报错
- 依赖装在哪个 Python 环境都行，`vendor/` 只是可选的本地安装方式

所以整个文件夹可以直接拷到另一台机器、另一个盘上运行。

## 出问题时

页面上的「API 诊断」按钮会把当前登录态、作品列表接口、详情接口、小说接口的返回结构
打印到日志里。遇到「下载 0 个文件」这类情况，先点它，把日志贴出来就能定位是登录态
问题还是接口变动。

## 项目结构

```
pixiv-downloader/
├── run.py                启动入口（自动开浏览器）
├── requirements.txt
├── run_tests.py          极简测试运行器（不依赖 pytest）
├── pixiv_dl/
│   ├── naming.py         命名与目录规则（纯函数，有单测）
│   ├── index.py          下载索引（查重：固定「作品 → 文件名」的映射）
│   ├── api.py            Pixiv 接口客户端（限速/重试/防盗链/系列展开）
│   ├── downloader.py     计划生成 + 下载执行（图片/动图GIF/小说）
│   ├── login.py          用系统 Chrome + CDP 取登录态
│   └── server.py         FastAPI 路由 + SSE 进度
├── web/                  GUI 页面
├── tests/                单测
├── dev_*.py              调试脚本（抓清单、跑接口、验证登录态）
├── .gitignore
├── .profile/             浏览器资料（运行时生成，不入库）
└── .state/               配置与 Cookie（运行时生成，不入库）
```
